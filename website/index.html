How it works

From empty canvas to a live build in four moves.

01 — DESIGN

Draw the farm

Drag a Server, Worker and Redis onto the canvas, or start from a Full RBE or Cache-only preset. Tune CPU and memory per node.

02 — PROVISION

Submit Setup

Real bazelbuild/buildfarm containers come up through Docker Compose, with a stable port per workspace.

03 — BUILD

Point Bazel at it

Download the generated sample project. Its .bazelrc already targets your farm, so a plain bazel build just works.

04 — WATCH

See everything

Status, targets, cache hits and failure reasons stream in as Bazel runs. Open any build for a timing waterfall and its outputs.

Cache-only mode

Just want a shared cache?

Turn remote execution off on the Worker. It still stores blobs; actions run on your machine and share results through it.

Workspaces

Each workspace gets its own farm.

Sign up, create workspaces, and provision an isolated Buildfarm for each, with its own ports, config and build history.

Yours to run

Where Croft fits

Not a smaller BuildBuddy. A place to learn your farm before you rent one.

Managed platforms like BuildBuddy, EngFlow and NativeLink are built for fleets. Croft is built for the moment before that.

Reach for Croft when
  • You're deciding what topology a Buildfarm needs before committing to a vendor.
  • You want remote caching or execution on a laptop or a single box.
  • Everything has to stay self-hosted, with no cloud account.
  • You want to see exactly what Bazel's Build Event Protocol carries.
Reach for a managed platform when
  • You need workers spread across many hosts, or elastic scaling.
  • You need SSO, roles and audit for a whole organisation.
  • CI at scale needs a network-reachable endpoint, not localhost.
  • Compliance like SOC 2 is on the checklist.

Quickstart

Running in a few minutes.

Clone it, start the database, start three services, open the app. Full steps live in SETUP.md.

Node 20+DockerPython 3.11+Bazel or Bazelisk
# one-time setup
git clone https://github.com/senthilaim/croft.git && cd croft
npm install
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env.local
cp automation/.env.example automation/.env
(cd automation && python3 -m venv venv && . venv/bin/activate \
  && pip install -r requirements.txt && ./generate_protos.sh)

# start
docker compose -f docker-compose.platform.yml up -d
npm run dev:backend      # :4000
npm run dev:automation   # :9000 + BES :9095
npm run dev:frontend     # :3000

Then open localhost:3000, sign up, create a workspace and draw your farm. Read SETUP.md →
